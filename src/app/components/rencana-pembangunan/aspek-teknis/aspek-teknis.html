B. Aspek Teknis & Operasional

1. Metode Pemilihan Lokasi

Penentuan lokasi operasional KamiTech di Jl. Karapitan No. 116, Bandung merupakan keputusan strategis yang dihasilkan melalui tiga metode evaluasi komprehensif sebagai berikut:

Penilaian Hasil Value

Menggunakan scoring method dengan bobot kriteria: kedekatan talent pool (30%), biaya operasional (25%), konektivitas internet (20%), aksesibilitas klien (15%), dan lingkungan bisnis (10%). Bandung memperoleh skor tertinggi dibandingkan kota kompetitor.

Perbandingan Biaya

Biaya overhead di Bandung 30—40% lebih rendah dari Jakarta (Numbeo, 2025). Sewa kantor, UMK, dan biaya hidup tim engineer lebih efisien, memungkinkan alokasi anggaran lebih besar pada infrastruktur teknologi dan pengembangan talenta.

Analisis Ekonomi

Bandung memiliki ekosistem startup peringkat ke-3 nasional (StartupBlink, 2025) dan didukung kebijakan pemerintah daerah sebagai Smart City. ROI pemilihan lokasi Bandung diproyeksikan 18% lebih tinggi dari kota kompetitor.

2. Luas Lingkup Produksi

Kapasitas dan lingkup produksi KamiTech ditentukan berdasarkan empat faktor fundamental yang memastikan operasional perusahaan berjalan optimal dan berkelanjutan yang merupakan adaptasi konsep untuk bisnis jasa:

Perkiraan Future Demand

Berdasarkan proyeksi e-Conomy SEA 2025, pertumbuhan ekonomi digital Indonesia diperkirakan mencapai US$130 miliar di 2030 (CAGR ~12%). KamiTech menargetkan kapasitas produksi awal 2.750 billable hours/bulan dengan skalabilitas hingga 5.000 jam pada tahun ke-3 operasional.

Ketersediaan SDM

Bandung menghasilkan 15.000+ lulusan IT/tahun dari universitas terkemuka (ITB, Telkom University, UNPAD). KamiTech memanfaatkan talent pool ini untuk merekrut 17 personel berkualitas dengan spesialisasi DevSecOps, Full-Stack, dan QA Engineering.

Support & Infrastruktur

Dukungan infrastruktur mencakup koneksi internet 5G dedicated, layanan cloud hosting AWS/GCP dengan SLA 99.95%, serta akses ke komunitas developer aktif dan program inkubasi dari Bandung Techno Park serta Telkom University.

Ketersediaan Bahan Baku

Bahan baku utama berupa lisensi software (Microsoft 365, GitHub Copilot, Figma), perangkat keras (laptop development-grade), dan layanan cloud yang seluruhnya tersedia secara on-demand tanpa kendala rantai pasok fisik konvensional.

5. Manajemen Persediaan
Penyerahan Hasil (Delivery)

Deliverable proyek (source code, dokumentasi, deployment) diserahkan melalui staging server secara bertahap di setiap akhir sprint (2—4 minggu). Sistem CI/CD memastikan delivery otomatis ke production server setelah melewati tahap QA.

Pencegahan Keterlambatan

Penerapan Agile Scrum dengan daily standup, sprint review, dan backlog grooming mencegah bottleneck. Monitoring via Clickup & Slack memastikan setiap task teridentifikasi statusnya secara real-time.

Persiapan Kebutuhan Tambahan

Cadangan kapasitas server cloud (auto-scaling AWS), lisensi software tambahan, dan perangkat hardware pengganti selalu tersedia. Buffer sprint (20% kapasitas) dialokasikan untuk permintaan perubahan mendadak dari klien.

Spekulasi Perubahan Harga

Fluktuasi harga lisensi cloud (AWS/GCP) dan hardware (chip shortage) dimitigasi melalui kontrak Reserved Instance jangka panjang untuk cloud dan pengadaan hardware secara periodik tahunan untuk mengunci harga.

6. Economic Order Quantity (EOQ)
Rumus EOQ √(2DS/H)

D = Permintaan tahunan (est. 12 unit lisensi software besar); S = Biaya pemesanan per order (Rp 2.000.000); H = Biaya penyimpanan/tahun (Rp 500.000/lisensi). EOQ bertujuan mengidentifikasi jumlah unit produk yang optimal untuk dipesan sehingga total biaya pemesanan dan penyimpanan persediaan dapat diminimalkan (Utami, 2018).

Dalam konteks IT, EOQ diterapkan pada pengadaan lisensi perangkat lunak, pembelian perangkat keras (laptop batch), dan perpanjangan layanan cloud. KamiTech mengoptimalkan pembelian dalam batch kuartalan untuk memperoleh diskon volume dan mengurangi frekuensi administrasi pengadaan (Utami, 2018).

7. Safety Stock
Formula Z x σ x √L

Z = Service level factor (1.65 untuk 95%); σ = Standar deviasi permintaan; L = Lead time pengadaan. Safety stock adalah jumlah barang yang disimpan perusahaan untuk mencegah kehabisan stok yang mungkin terjadi karena perubahan penawaran atau permintaan secara tiba-tiba (Sia, 2023).

KamiTech mempertahankan safety stock berupa: 2 unit laptop cadangan untuk menggantikan kerusakan mendadak, cadangan kapasitas cloud 30% di atas kebutuhan rata-rata, serta buffer lisensi software 2 seat untuk kebutuhan onboarding karyawan baru secara cepat.

8. Reorder Point (ROP)

Reorder point atau titik pemesanan ulang adalah tingkat tertentu di mana persediaan perlu diisi ulang oleh perusahaan untuk memastikan bisnis dapat terus memenuhi pesanan (Sia, 2023). ROP dihitung berdasarkan rata-rata penggunaan harian, lead time pengadaan, dan safety stock yang telah ditetapkan.

Rumus ROP (d x L) + SS

d = Rata-rata penggunaan harian; L = Lead time pengadaan; SS = Safety stock.

Pemesanan ulang lisensi software dilakukan saat sisa masa aktif mencapai 60 hari (lead time perpanjangan ~30 hari + buffer). Untuk hardware, ROP ditetapkan saat stok cadangan tersisa 1 unit dengan lead time pembelian 14—21 hari kerja.

ROP Lisensi Software

Pemesanan ulang dilakukan saat sisa masa aktif lisensi mencapai 60 hari. Buffer 30 hari disiapkan untuk mengantisipasi proses perpanjangan yang membutuhkan negosiasi vendor.

ROP Perangkat Keras

Pemesanan dilakukan saat stok cadangan tersisa 1 unit. Lead time pembelian diperhitungkan selama 14—21 hari kerja dengan evaluasi vendor secara berkala.

ROP Kapasitas Cloud

Auto-scaling trigger diaktifkan saat penggunaan mencapai 70% kapasitas. Reserved Instance diperpanjang 90 hari sebelum masa berakhir untuk mengunci tarif.

Notifikasi Otomatis

Sistem notifikasi otomatis terintegrasi pada dashboard inventaris internal KamiTech, memastikan setiap titik reorder terdeteksi dan ditindaklanjuti tepat waktu.

Dengan penerapan ROP yang terstruktur, KamiTech memastikan ketersediaan sumber daya operasional secara kontinu tanpa terjadi gangguan layanan akibat kekosongan persediaan (Sia, 2023). Integrasi notifikasi otomatis pada dashboard internal mempercepat respons pengadaan dan meminimalkan risiko downtime operasional.
